# 验收手册：五个规定场景的操作路径

启动：`npm run dev`（嵌入式真实 PG）→ http://localhost:4000 。
管理口令 `dev-admin-key`（Docker 为 `change-me-in-production`）。

## 1. 断网重试

1. 打开「报名课次」，填好姓名/联系方式，点「我要报名」拿到倒计时。
2. 在确认前**断开网络**（DevTools → Network → Offline，或拔网）。
3. 点「确认报名」：顶部出现离线横幅，操作进入本机发件箱（不会有任何成功假象）。
4. 恢复网络：发件箱自动重放。由于确认请求带稳定幂等断网重试天然只执行一次。
   （测试：`同一幂等键重复请求只产生一个占位，第二次回放`；同键不同体被 409。）

## 2. 同时报名（最后一个名额）

1. 「扎染方巾·冷染体验课」容量 2。先让一个账号确认第 1 个名额。
2. 用**两个浏览器/无痕窗口**（或 curl 并发）同时点「我要报名」。
3. 一个显示「名额保留中（倒计时）」，另一个直接进入「已候补」；
   列表剩余名额对两者都是 0，绝不会两个都显示可确认最后一个。
4. 同一人两台设备：第二个窗口查询或报名时返回 already_enrolled。
   （测试：`容量 2，已有 1 人确认 → 两个并发占位请求恰好只有 1 个拿到 hold，另一个候补`。）

## 3. 活动改期

1. 任一已确认报名后，进入管理后台 → 课次与席位 → 选新时间 → 「改期为所选时间」。
2. 学员的「我的报名」出现黄色「活动已改期」提示，同时展示原时间与新时间；
   报名状态不变、记录不删（schedule_version 由 1 变 2，可核验）。

## 4. 作品换图

1. 管理后台 → 作品发布 → 选「蓝白方巾」→ 填 `/assets/hero.svg` → 「登记新图并换为草稿封面」。
2. 此时**线上故事页仍是旧图**（草稿与发布版本分离）。
3. 点「发布新版本」→ 故事页切到新图，版本号 v1→v2；旧版本快照仍在 `work_versions`。

## 5. 授权到期

- 种子数据刻意安排：
  - 「蓝白方巾」：展示有效但**教学授权已撤回** → 故事页有封面、无步骤，黄色…不对，暗红提示；
  - 「人字纹茶则」：**展示授权约 2 小时后到期**、教学长期有效 → 到期后封面消失但步骤仍在；
  - 「六瓣窗花」：管理后台手动撤回 display → 封面立即下线，步骤照常。
- 关键不变量：授权状态如何变化，已确认/已取消的报名记录都还在；
  关联课次仍可查询，课程不因为版权状态而「被删除」。

## 主动放弃与候补顺序

1. 将「扎染」容量保持 2：两人取得保留、另两人满员候补。
2. 第一位保留者点「放弃保留」：接口 `POST /api/bookings/holds/:id/release` 立即生效，
   不必等待 TTL；返回的 `promoted[0]` 必须是最早的候补者。
3. 第二位候补仍为 `waiting`；被邀请者超时未确认后，名额再继续顺延给下一位。

## 「席位不可用」与「内容不可用」的区分

| 场景 | 错误码 | 页面提示 | 提示条颜色 |
| --- | --- | --- | --- |
| 占位超时 | HOLD_EXPIRED | 保留超时，名额已回收顺延给候补 | 黄 |
| 减容量 | CAPACITY_REDUCED | 管理员下调容量，可转候补 | 黄 |
| 2 浏览器重复 | ALREADY_ENROLLED | 另一页面已完成，无需重复 | 黄/绿 |
| 展示授权问题 | cover=null + availability_note | 展示许可未生效/撤回/到期 | 暗红 |
| 教学授权问题 | steps=[] + availability_note | 教学许可未生效/撤回/到期 | 暗红 |
